# Веб‑сервер проверки доступности ссылок

HTTP‑сервис принимает одну или несколько ссылок на интернет‑ресурсы, проверяет их доступность и возвращает статусы (`available` / `not available`) вместе с номером набора (`links_num`). Также сервис умеет генерировать PDF‑отчёт по ранее сохранённым наборам ссылок.

## Запуск

### 1) Установка зависимостей
```bash
go mod download
```

### 2) Запуск сервера
```bash
go run ./cmd/wm/main.go -config ./config/config.yaml
```

Параметр `-config` задаёт путь до конфигурационного файла.

## Конфигурация

Файл `config/config.yaml` содержит основные настройки:
- `server.Addr` — адрес/порт HTTP сервера (например, `0.0.0.0:8080`)
- `server.ReadTimeout`, `server.WriteTimeout`, `server.IdleTimeout` — таймауты HTTP сервера
- `server.ShutdownTimeout` — таймаут на graceful shutdown
- `client.Timeout` — таймаут HTTP‑клиента при проверке ссылок
- `storage.DataDir` и `storage.FileName` — путь к файлу для сохранения состояния

## API

### POST /links
Проверяет доступность одной или нескольких ссылок.

**Request**
```json
{"links":["google.com","malformedlink.gg"]}
```

**Response**
```json
{"links":{"google.com":"available","malformedlink.gg":"not available"},"links_num":1}
```

Примечания:
- Если ссылка пришла без схемы (`http://` или `https://`), сервис автоматически добавляет `http://`.
- “available” считается ответ со статус‑кодом `< 400`. Иначе — “not available”.

### POST /report
Генерирует PDF‑отчёт по сохранённым наборам ссылок.

**Request**
```json
{"links_list":[1,2]}
```

**Response**
- `200 OK`
- `Content-Type: application/pdf`
- Файл `report.pdf` со списком URL и их статусами.

Если один из `links_num` не найден — возвращается `404`.

## Допущения и ограничения

- Максимальный размер тела запроса: 1MB (для обоих эндпоинтов).
- Результаты хранятся in-memory; для восстановления после перезапуска используется сохранение/загрузка состояния в JSON‑файл.
- Во время остановки (graceful shutdown) новые запросы получают `503 Service Unavailable`.

## Хранение состояния

Результаты хранятся in-memory, дополнительно состояние сохраняется в файл (JSON):
- При старте сервис пытается загрузить состояние из файла (если файл существует).
- При остановке сервис делает graceful shutdown и сохраняет состояние в файл.

## Остановка (graceful shutdown)

Сервис обрабатывает `SIGINT`/`SIGTERM`:
- переводит сервер в режим остановки,
- завершает HTTP‑сервер через `Shutdown` с таймаутом,
- сохраняет состояние в файл.

Во время остановки новые запросы могут получать `503 Service Unavailable` (режим “сервер завершает работу”).

## Разработка и CI

В репозитории настроен GitHub Actions workflow (`.github/workflows/ci.yml`), который автоматически запускается при пуше и Pull Request в ветки `main`, `home`, `hw`.

Проверки включают:
- Загрузку зависимостей (`go mod download`)
- Статический анализ (`go vet`)
- Запуск тестов с детектором гонок (`go test -v -race ./...`)
- Сборку проекта (`go build`)

### Локальное тестирование

Для быстрой проверки работоспособности API можно использовать скрипт `testserv.py` (требует Python 3). Он выполняет базовый сценарий проверки ссылок:

```bash
python3 testserv.py
```

Убедитесь, что сервер запущен на порту 8080 (или измените `BASEURL` в скрипте).
